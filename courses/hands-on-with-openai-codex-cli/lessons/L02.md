# Lesson 2: Write the task contract before the change

## Objective

Turn "make it better" into bounded, testable statements — the single highest-leverage skill for driving Codex.

## The lesson

Open `TASK.md`. Every line names an observable behavior, not an implementation. Trace four statements to their tests, then write one contract line for a script you own. Boundary clauses (only `starter/report_tool.py`, stdlib only, no test edits) are what keep an agent's helpful rewrite from swallowing your project.

## Exercise

- Ask Codex to critique your contract against TASK.md — it should find ambiguities, not add features
- Ask: "which of these could you satisfy by cheating?" Fix any line that fails that test

## Checkpoint

The lesson's commands run, and you can explain — in your own words — what failed and why.

## Expected evidence

The command transcript and your answers. Lesson 4 asks for them again.
