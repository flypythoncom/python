# Lesson 5: Apply this to your own project

## Objective

Port the workflow — not the code — to one script you own, with tests, a verify command, and honest limits.

## The lesson

Pick the script you run repeatedly and mildly fear. Write its contract (three behavior statements, one boundary clause, one acceptance command), add one failing test for the scariest line, have Codex make it pass under lesson 3's rules, and write the verification record. Remember what passing tests do not prove: tomorrow's data, production scale, upstream schema changes. Your outcome is a user-visible behavior; tests are the evidence.

## Exercise

- Run your acceptance command from a clean checkout to prove it does not depend on your machine

## Checkpoint

The lesson's commands run, and you can explain — in your own words — what failed and why.

## Expected evidence

The command transcript and your answers. Lesson 4 asks for them again.
